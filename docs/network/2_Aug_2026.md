# SSL/TLS Certificates Lab Notes (Ubuntu + Nginx + OpenSSL)

## Objective

Learn the basics of SSL/TLS certificates by:

* Generating a self-signed certificate.
* Configuring Nginx to use HTTPS.
* Understanding where certificates are stored.
* Debugging common Nginx SSL configuration issues.

---

# Environment

* Ubuntu Server (VirtualBox)
* Nginx 1.24.0
* OpenSSL
* No public domain
* Self-signed certificate

---

# Directory Setup

Created a dedicated directory for SSL certificates:

```bash
sudo mkdir -p /etc/nginx/ssl
```

---

# OpenSSL

Generated:

* Private Key
* Certificate Signing Request (CSR)
* Self-Signed Certificate

Files created:

```
server.key
server.csr
server.crt
```

Initially these were located in:

```
/home/vboxuser/
```

Moved them to:

```
/etc/nginx/ssl/
```

Example command:

```bash
sudo mv server.crt /etc/nginx/ssl/
sudo mv server.csr /etc/nginx/ssl/
sudo mv server.key /etc/nginx/ssl/
```

Verify:

```bash
ls -l /etc/nginx/ssl
```

---

# Nginx HTTPS Configuration

Added a separate HTTPS server block.

Important directives:

```nginx
server {
    listen 443 ssl;

    server_name localhost;

    ssl_certificate /etc/nginx/ssl/server.crt;
    ssl_certificate_key /etc/nginx/ssl/server.key;

    root /var/www/html;
    index index.html;
}
```

---

# Testing Configuration

Always test before restarting Nginx:

```bash
sudo nginx -t
```

If successful:

```bash
sudo systemctl reload nginx
```

or

```bash
sudo systemctl restart nginx
```

# Debugging Process

## Issue 1

Error:

```
invalid number of arguments in ssl_certificate directive
```

### Initial Thoughts

Checked:

* Certificate paths
* Nginx version
* SSL directory
* Separate server block
* HTTP vs HTTPS configuration
* File locations

None of these solved the issue.

---

## Root Cause

The problem was **syntax**.

The certificate path had accidentally been split across two lines.

Incorrect:

```nginx
ssl_certificate /etc/nginx/ssl/
server.crt;
```

Correct:

```nginx
ssl_certificate /etc/nginx/ssl/server.crt;
```

Nginx expects the entire directive to be on **one line**.

---

## Lesson Learned

Many Nginx errors are caused by:

* Missing semicolons
* Incorrect braces
* Line breaks
* Invalid syntax

Not necessarily by the certificate itself.

# Key Concepts Learned

* Difference between:

  * Private Key (`.key`)
  * CSR (`.csr`)
  * Certificate (`.crt`)
* Nginx server blocks
* HTTPS uses port **443**
* HTTP uses port **80**
* Certificates should reside on the server itself
* Nginx reads certificates from the configured path
* Self-signed certificates are sufficient for local testing

# Biggest Takeaway

Platform Engineering is not about memorising commands.

It is about:

1. Build.
2. Test.
3. Read the error.
4. Form a hypothesis.
5. Fix one thing.
6. Test again.
7. Repeat.

Today's session reinforced that small syntax mistakes can prevent an entire service from starting.
