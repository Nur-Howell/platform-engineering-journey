# OpenSSL Self-Signed Certificate Lab

## Objective

Learn how to generate a self-signed SSL/TLS certificate using OpenSSL for local testing with Nginx.

---

# Prerequisites

Verify OpenSSL is installed:

```bash
openssl version
```

---

# Create SSL Directory

Create a dedicated location for certificates:

```bash
sudo mkdir -p /etc/nginx/ssl
```

Move into the directory (recommended):

```bash
cd /etc/nginx/ssl
```

---

# Step 1 - Generate a Private Key

Generate a 2048-bit RSA private key.

```bash
sudo openssl genrsa -out server.key 2048
```

Output:

```text
server.key
```

### Purpose

* This is the **private key**.
* Never share this file.
* It is used by the server to decrypt encrypted traffic.

---

# Step 2 - Generate a Certificate Signing Request (CSR)

Create a CSR using the private key.

```bash
sudo openssl req -new -key server.key -out server.csr
```

During creation, OpenSSL asks for information such as:

* Country
* State
* Locality
* Organisation
* Organisational Unit
* Common Name
* Email Address

For local testing, most fields can simply be left blank or filled with test values.

Output:

```text
server.csr
```

### Purpose

A CSR contains:

* Your public key
* Information about the server
* Identity information

Normally this file would be sent to a Certificate Authority (CA).

---

# Step 3 - Generate a Self-Signed Certificate

Instead of sending the CSR to a Certificate Authority, sign it yourself.

```bash
sudo openssl x509 -req \
-days 365 \
-in server.csr \
-signkey server.key \
-out server.crt
```

Output:

```text
server.crt
```

### Purpose

This creates a certificate valid for **365 days**.

Because it is self-signed:

* Browsers will warn that it is **not trusted**.
* Perfectly acceptable for:

  * Local testing
  * Homelabs
  * Learning
  * Internal services

---

# Files Created

```text
server.key
server.csr
server.crt
```

---

## File Summary

### server.key

Private Key

* Secret
* Never share publicly
* Used by the server

---

### server.csr

Certificate Signing Request

Contains:

* Public key
* Identity information

Normally sent to:

* Let's Encrypt
* DigiCert
* GlobalSign
* Cloudflare Origin CA
* Other Certificate Authorities

---

### server.crt

Certificate

Contains:

* Public key
* Identity
* Digital signature

Presented to clients during the TLS handshake.

---

# Moving Existing Certificates

If certificates were generated elsewhere (for example inside `/home/vboxuser`):

```bash
sudo mv server.key /etc/nginx/ssl/
sudo mv server.csr /etc/nginx/ssl/
sudo mv server.crt /etc/nginx/ssl/
```

Verify:

```bash
ls -l /etc/nginx/ssl
```

Expected:

```text
server.crt
server.csr
server.key
```

---

# Nginx Configuration

Inside the HTTPS server block:

```nginx
ssl_certificate /etc/nginx/ssl/server.crt;
ssl_certificate_key /etc/nginx/ssl/server.key;
```

---

# Test Configuration

Always validate before reloading:

```bash
sudo nginx -t
```

Reload:

```bash
sudo systemctl reload nginx
```

---

# Browser Test

Open:

```text
https://localhost
```

Expected:

* Browser warns that the certificate is self-signed.
* Proceed anyway.
* HTTPS connection works successfully.

---

# Common Errors

## 1. Invalid number of arguments

Cause:

```nginx
ssl_certificate /etc/nginx/ssl/
server.crt;
```

Correct:

```nginx
ssl_certificate /etc/nginx/ssl/server.crt;
```

---

## 2. No such file or directory

Cause:

```text
/etc/nginx/ssl
```

did not exist.

Fix:

```bash
sudo mkdir -p /etc/nginx/ssl
```

---

## 3. Wrong certificate path

Verify:

```bash
ls -l /etc/nginx/ssl
```
